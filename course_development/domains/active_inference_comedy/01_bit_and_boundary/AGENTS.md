# Agent Guidelines: Bit & Boundary

> **Quick Navigation**: [Domain AGENTS](../AGENTS.md) | [Course README](./README.md)

## Course-Specific Conventions

- **Perspective**: The routine as a system — analyzing comedy from the outside in, mapping the formal structure of comedic exchange onto Active Inference
- **Tone**: Smart, antic, deeply technical, never condescending — like a linguist who moonlights at open mics
- **Grounding**: All concepts grounded in "Who's on First?" analyzed as a bounded dynamical system
- **Lab Style**: Routine Analysis Lab — dissecting recorded performances, mapping system boundaries, identifying internal and external states

## Active Inference Integration

In Bit & Boundary, the core mappings are:

| Comedy Concept | Active Inference Concept | Why It Matters |
|---------------|------------------------|----------------|
| The routine | A bounded dynamical system | Comedy has structure that persists and self-maintains |
| Dialogue | Markov blanket (sensory + active states) | Words are the boundary where internal beliefs meet external world |
| Abbott's certainty | High-precision generative model | The straight man's model is rigid by design |
| Costello's confusion | Volatile model with persistent prediction error | The comic's model never accommodates the data |
| Audience laughter | External state feedback crossing the blanket | The audience is outside the routine but coupled to it |
| The bit holding together | System maintaining itself against dissolution | A good routine resists entropy |

## Content Standards

1. Every `module.md` must treat the routine as the primary object of analysis — not the performers, not the audience, but the system itself
2. Every `questions.md` must ground questions in specific moments from "Who's on First?" or analogous routines
3. Every `practice_quiz.md` must include both MC and short-answer sections with comedy-specific scenarios
4. Every `lab.md` must involve actual analysis of recorded comedy — listening, mapping, diagramming
