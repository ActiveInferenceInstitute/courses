## 重要なルール（すべてのエージェント向け）

### 1. 共有リソースを最初に参照する

生成または編集するコンテンツを作成する前に、次のファイルを確認してください。

| リソース | 目的 | 参照するタイミング |
|----------|---------|----|
| [resources/notation_table.md](./resources/notation_table.md) | **標準記号** | どの数式、記号、または方程式を書くか作成する前に |
| [resources/glossary.md](./resources/glossary.md) | **標準定義** | どの技術用語を使用または定義するか前に |
| [resources/references.md](./resources/references.md) | **標準参照** | どの論文または教科書を引用するか前に |
| [resources/cross_course_map.md](./resources/cross_course_map.md) | **コース間のリンク** | コース間でクロス参照を追加する前に |

### 2. プレースホルダーは決して使用しない

すべてのコンテンツは、**実際のメソッド**を使用する必要があります—モック、スタブ、プレースホルダーの角括弧、または `[TODO]` マーカーは使用しません。すべてのモジュールには、説得力があり、正確なコンテンツが含まれている必要があります。

### 3. コース固有の視点を維持する

| コース | 視点 | 実験の種類 | 例のコンテンツ |
|--------|--------|----------|----------------|
| 哲学 | 哲学的な議論 | 思考実験 | 「マルコフの被覆は自己について何を意味しますか？」 |
| 認知科学 | 神経コーレレーションと臨床 | ケーススタディ分析 | 「予測コーディングはphantom limbの痛みについてどのように説明しますか？」 |
| 数学 | 正式な導出と証明 | 導出の演習 | 「EFE 分解をリスクと曖昧さの関数として導出する」 |
| コンピュータサイエンス | カスタム `active_inference` ライブラリ | コーディングの実験 | 「T-maze エージェントを実装し、信念を視覚化する」 |

## 記号の基準

すべてのコースで、[resources/notation_table.md](./resources/notation_table.md) で定義された記号を使用します。主な記号:

| 記号 | 意味 | LaTeX |
|--------|---------|-------|
| `F` | 離散エネルギー | `$F$` |
| `G` | 期待される離散エネルギー | `$G$` |
| `π` | ポリシー（行動のシーケンス） | `$\pi$` |
| `q(s)` | 状態に対する近似後方分布 | `$q(s)$` |
| `p(o,s)` | 生成モデル（共役） | `$p(o,s)$` |
| **A** | 確率行列 | `$\mathbf{A}$` |
| **B** | 遷移行列 | `$\mathbf{B}$` |
| **C** | 偏好ベクトル | `$\mathbf{C}$` |
| **D** | 事前状態分布 | `$\mathbf{D}$` |
| **E** | 習慣ベクトル（ポリシーの事前分布） | `$\mathbf{E}$` |
| `η, μ, σ, α` | 外、内、感覚、アクティブな状態 | `$\eta, \mu, \sigma, \alpha$` |
| `γ` | ポリシーの精度（逆温度） | `$\gamma$` |
| `β` | 感覚の精度（逆分散） | `$\beta$` |
| `D_KL` | KL 分散 | `$D_{KL}$` |
| `S` | 驚異：`-ln p(o)` | `$\mathfrak{S}$` |

完全な記号（学習されたパラメータ、分解、時間的記号、および慣例を含む）については、[resources/notation_table.md](./resources/notation_table.md) を参照してください。

## 用語の基準

| 優先用語 | 避けるべき | 理由 |
|----------------|-------|--------|
| 生成モデル | 世界モデル、内部モデル | 標準的な FEP 用語 |
| 生成プロセス | 環境、真の世界 | 生成モデルとは区別 |
| マルコフの被覆 | 境界、インターフェース（非公式） | ベーヨルियन統計学における正式な用語（パール） |
| 精度 | 信頼性、確実性 | 精度 = 逆分散（特定の意味） |
| 認知密度 | 認識 | 標準的な変分インférence用語 |
| 被覆状態 | 境界状態 | 正式：感覚とアクティブな状態の合体 |
| アクティブな状態 | 行動状態、運動状態 | 正式マルコフ被覆分割の用語 |
| 感覚状態 | 入力状態、観察状態 | 正式マルコフ被覆分割の用語 |
| ポリシー | 計画、戦略（非公式） | 正式：行動のシーケンス（a₁,...,aₜ） |
| 知識的価値 | 好奇心、探索ボーナス | EFE の成分 |
| 実用的価値 | ユーティリティ、報酬 | EFE の成分 |
| 離散エネルギー (VFE) | 離散エネルギー（曖昧） | 熱力学的離散エネルギーとは異なるもの。観測ログの対数証拠の限界 |
| 期待される離散エネルギー (EFE) | 将来の離散エネルギー | ポリシー π の関数。リスクと曖昧さの成分 |
| 驚異 | 驚き（口語） | 技術用語：`-ln p(o)` |

完全な用語集（定義を含む）については、[resources/glossary.md](./resources/glossary.md) を参照してください。

## トピックの順序に関する規則

すべての4つのコースで、次の順番でトピックが使用されます。

1. **システム** → 2. **エージェント** → 3. **感覚** → 4. **認知** → 5. **行動** → 6. **学習** → 7. **コミュニケーション** → 8. **計画**

この順序は固定されており、変更することはできません。これは、論理的な依存関係のシーケンスを反映しています。

## コンテンツ形式の基準（biol-1 準拠）

すべてのコンテンツファイルは、`biol-1/course` からのフォーマット規則に従います。

| ファイル | 形式要件 |
|------|-------------------|
| `module.md` | `# タイトル: サブタイトル` → 導入 → 学習目標 → キー用語 → コア概念（5つのセクション） → 例 → 概要 → 参考文献 |
| `questions.md` | `# コース — モジュール — 学習問題` + 単純な番号付きリスト（20の質問）。リスト内にはセクションヘッダーを含めない |
| `practice_quiz.md` | `名前/日付` ヘッダー → `パート A: 選択肢`（7の質問、`**1.**` の番号付け、 `A) ... B) ...` 形式） → `パート B: フリーレスポンス`（3の質問） |
| `lab.md` | `目的` → 複数部分で `> **学習目標:**` ブロック引用符 |
| `<!-- lab:reflection -->` / `{fill:textarea}` フィールド → `まとめ` テーブル |
| `dashboard.html` | インタラクティブな HTML5: ダークテーマ、概念カード、進捗メーター、質問、アニメーショントランジションを含む JavaScript |
| `README.md` | クイックナビゲーションのヘッダー、概要、モジュールコンテンツのテーブル、クロス参照、ナビゲーションのフッター |
| `AGENTS.md` | クイックナビゲーションのヘッダー、ディレクトリコンテンツのテーブル、コンテンツ生成のガイドライン |

## コンテンツ生成の基準

* すべてのコンテンツは、**実際のメソッド**を使用する必要があります—モック、スタブ、プレースホルダーの角括弧、または `[TODO]` マーカーは使用しません。
* モジュールのコンテンツは、**モジュール化、関数型、およびドキュメント化**されている必要があります。
* 各モジュールは、**自律的**である必要がありますが、カリキュラムにおける位置を認識する必要があります。
* 実験は、そのコースのドメインに適した、**実践的な、実行可能な**演習を含める必要があります。
* ダッシュボードは、**インタラクティブな HTML** で、動作する JavaScript が含まれている必要があります。
* すべての記号は、[resources/notation_table.md](./resources/notation_table.md) で定義されたものと一致する必要があります。
* すべての用語は、[resources/glossary.md](./resources/glossary.md) で定義されたものと一致する必要があります。
* すべての参照は、可能な限り、[resources/references.md](./resources/references.md) から取得される必要があります。
* 哲学コースは、**段階的なオンボーディング**を使用します。モジュール 1 は、前提条件なしで開始し、徐々に構築されます。
* コンピュータサイエンスコースは、`04_computer_science/src/active_inference/` 内の `active_inference` ライブラリを使用します（サブパッケージ: `agent/`, `math/`, `visualization/`）。実験とモジュールコンテンツのコード例は、このライブラリからインポートする必要があり、raw pymdp からはインポートしないでください。
* 各コースの学習問題は、そのコースの**学問的視点**を反映している必要があります。
* クイズの質問は、**答えられる**モジュールコンテンツから得られる必要があります。
