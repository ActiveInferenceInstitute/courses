## コース固有の慣例

- **視点**: すべてのコンテンツは、**数学的**な視点からフレーム化される必要があります。
- **ラボタイプ**: ラボは**導出演習**形式を使用します—証明の構築、方程式の操作、および解決例。
- **注釈**: [リソース/notation_table.md](../resources/notation_table.md) から注釈を使用してください。
- **用語**: [リソース/glossary.md](../resources/glossary.md) から用語を使用してください。
- **参照**: [リソース/references.md](../resources/references.md) から参照してください。

## コンテンツ生成基準

- すべてのコンテンツは**実用的な方法**を使用します—モック、スタブ、またはプレースホルダーの実装は使用しません。
- モジュールコンテンツは**モジュール化、関数型、ドキュメント化**されている必要があります。
- 質問は各モジュールあたり**20個**で、単なる番号付きリストの形式で書かれる必要があります。
- すべての20個の質問は、このコースの**数学的**な視点を反映している必要があります。
- クイズは**パートA: 7個の選択肢の複数選択** + **パートB: 3個の自由記述**で構成されます。
- ラボは**構造化された部分**と学習目標、および `{fill:textarea}` フィールドで構成されます。
- ラボの概要テーブルは、**完全で切り詰められていない**スキル記述を含める必要があります。
- ダッシュボードは**インタラクティブな HTML5** で、動作する JavaScript を使用する必要があります。
- 他のコースの並行モジュールへのクロス参照は、相対パスを使用する必要があります。
